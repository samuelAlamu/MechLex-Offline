MECHLEX 10.1.0 — מילון הנדסי אופליין עם עריכת אדמין חזותית
========================================================

מטרת המסמך
-----------
README זה הוא נקודת הכניסה הרשמית לפרויקט. הוא מרכז את מבנה המערכת, אופן ההפעלה,
הרשאות הניהול, שכבות השמירה והגיבוי, כללי הוספת תמונות, שדרוג גרסאות והנחיות להמשך
פיתוח בלי להתחיל מחדש ובלי לפגוע בנתונים קיימים.

לפני שינוי עתידי בפרויקט יש לקרוא, לפי הסדר:
1. README_HE.txt
2. VERSION.txt
3. CHANGELOG_HE.txt
4. TEST_REPORT_HE.txt
5. קובצי המקור הרלוונטיים

אין להשתמש במסמכי Word שבתיקיית "גיבוי וורד" כמקור להרצת המערכת או לעריכת הקוד.
מסמכי Word הם עותק תיעודי בלבד. קובצי המקור הרגילים הם מקור האמת.

מה המערכת עושה
---------------
MechLex הוא מילון ידע הנדסי אינטראקטיבי, עברי ו-RTL, המיועד לעבודה אופליין במחשב נייח
עם מסך גדול. המערכת מאפשרת:
- ניווט לפי תחום, תת-תחום ותת-תת-תחום.
- חיפוש לפי שם, שם באנגלית, קוד, סימון, תקן, תגית או מילת מפתח.
- תצוגת מושגים הכוללת הגדרה מקצועית, תמונה, נוסחה, משתנים, תקנים, שימושים,
  שיקולי ייצור, שיטות בחינה, דוגמאות ומושגים קשורים.
- מועדפים, מצב למידה והיסטוריית צפייה לכל משתמש במחשב ובדפדפן שלו.
- ניהול תוכן והרשאת אדמין ראשי בשתי דרגות גישה נפרדות.
- עבודה ללא אינטרנט וללא שירות ענן.

סביבת העבודה המיועדת
---------------------
- Windows 10 או Windows 11.
- Microsoft Edge 95 (דפדפן דפולטי בארגון) או Google Chrome מקביל מ-2021.
- מסך מחשב נייח; מומלץ 1920×1080 ומעלה.
- מיועד לשימוש במצב offline ברשת פנימית בארגון (LAN), שבו אין גישה לאינטרנט כלל.
- כל משתמש עובד עם עותק מקומי של תיקיית הפרויקט במחשב שלו, אלא אם הארגון בוחר
  בהמשך לפרוס את המערכת על שרת פנימי.

הפעלה נכונה
-----------
1. חלצו או העתיקו את כל תיקיית הפרויקט למיקום קבוע במחשב.
2. אין להוציא את index.html מהתיקייה ואין לשנות את שמות התיקיות core, data,
   images או backups.
3. הפעילו בלחיצה כפולה את START_MECHLEX.bat.
4. המילון ייפתח בכתובת:
   http://127.0.0.1:8765/index.html
5. יש להשאיר את חלון PowerShell הממוזער פתוח בזמן העבודה.
6. לסיום אפשר לסגור את חלון הדפדפן ואת חלון PowerShell.

אפשר ליצור קיצור דרך של START_MECHLEX.bat על שולחן העבודה ולשנות את שמו ל:
MechLex — מילון הנדסי

אין לפתוח את index.html ישירות כ-file:// לשימוש שוטף. פתיחה ישירה עלולה לגרום למגבלות
אבטחה של Edge, להפרדת אזורי אחסון ולפעולות שאינן מגיבות באופן עקבי.

מה עושה START_MECHLEX.bat
-------------------------
- מפעיל שרת מקומי בלבד על המחשב הנוכחי.
- פותח את המילון ב-Edge או בדפדפן ברירת המחדל.
- אינו שולח מידע לאינטרנט.
- אינו דורש התקנה או הרשאות שרת ארגוניות.
- אם פורט 8765 כבר מריץ את MechLex, הוא משתמש במופע הקיים; אם שירות אחר תופס את הפורט, נבחר אוטומטית פורט פנוי סמוך.

סדר טעינת הקוד — אין לשנות ללא בדיקה
------------------------------------
index.html טוען את הקבצים בסדר הבא:
1. data/mechlex-data.js
2. images/catalog.js
3. app.js
4. core/integrity.js
5. core/persistence.js
6. core/boot.js

boot.js חייב להיטען אחרון. שינוי הסדר עלול לגרום לכך שהמערכת תוצג אך לא תגיב.
לאחר שינוי שם קובץ, נתיב או גרסת cache ב-index.html יש לבדוק שכל הקבצים נטענים ללא
שגיאות Console.

חוויית המשתמש הרגיל
-------------------
המשתמש הרגיל יכול:
- לבחור תחום או רמה בהיררכיה.
- לחפש ולמיין מושגים.
- לעבור בין תצוגת כרטיסים לתצוגת רשימה.
- לפתוח מושג, להציג תמונה והגדרה ולהדפיס או לייצא אותו.
- להוסיף מושגים למועדפים.
- לסמן מצב למידה: טרם התחלתי, בתהליך או נלמד.
- להשתמש במסלול "הפתיעו אותי" למעבר אקראי בין מושגים ללא חזרה באותו מחזור.
- להוריד ולטעון קובץ מצב אישי הכולל מועדפים, התקדמות, היסטוריה והעדפות תצוגה.
- לעבור בין מצב בהיר לכהה.

הרשאות ומרכז הניהול
-------------------
הכניסה נעשית דרך הכפתור "מרכז ניהול" ובחירת דרגת הרשאה.

קודי ברירת המחדל בחבילה חדשה:
- מומחה תוכן / Content Admin: 1234
- אדמין ראשי / Super Admin: 9999

יש לשנות קודים אלה לאחר ההתקנה. הקודים נשמרים בדפדפן המקומי בלבד, אינם נכללים
בגיבויי JSON ומשמשים מחסום נוחות — לא מנגנון אבטחה ארגוני.

מומחה תוכן — Content Admin
--------------------------
מומחה התוכן מיועד לעבודה השוטפת על הקטלוג. הוא יכול:

ניהול מושגים
- ליצור מושג חדש; הקוד נוצר אוטומטית לפי קידומת התחום.
- לערוך מושג קיים.
- לשייך מושג ישירות לתחום, לתת-תחום או לתת-תת-תחום.
- לערוך הגדרה עשירה עם כותרות, הדגשה, רשימות וציטוט.
- להזין סימון, יחידות, תקציר, חשיבות, שמות חלופיים, תגיות ותקנים.
- להזין נוסחה, משתנים ודוגמה מחושבת.
- להזין שימושים, דגשים, שיקולי ייצור ושיטות בחינה.
- לקשר מושגים קשורים לפי קוד או שם.
- לציין שם קובץ תמונה מתיקיית images.
- להטמיע תמונה קטנה בתוך המושג והגיבוי, עד המגבלה המוצגת בממשק.
- לשכפל מושג. המערכת יוצרת קוד ייחודי גם בשכפול חוזר.
- למחוק מושג לאחר אישור. המערכת שומרת נקודת שחזור ומנקה הפניות שבורות.
- לחפש ולסנן את רשימת המושגים במרכז הניהול.

ניהול תחומים והיררכיה
- ליצור ולערוך תחום.
- לקבוע שם, שם באנגלית, קידומת קוד, סמל, צבע ותיאור.
- ליצור תתי-תחומים ותתי-תתי-תחומים.
- למחוק תחום ריק.
- למחוק תחום וכל תוכנו לאחר אישור מפורש ונקודת שחזור.

גיבוי בהרשאת תוכן
- כפתור הגיבוי העליון מוריד גיבוי תוכן.
- גיבוי התוכן כולל תחומים, היררכיה, מושגים ותמונות שהוטמעו בתוך המושגים.
- הוא אינו כולל קודי גישה, תמונות חיצוניות מתיקיית images או הגדרות UI/UX מלאות.

מומחה תוכן אינו מקבל גישה ללשוניות "תצוגה" ו"גיבוי ותחזוקה" של האדמין הראשי.

אדמין ראשי — Super Admin
------------------------
האדמין הראשי כולל את כל יכולות מומחה התוכן ובנוסף:

תצוגה ו-UI/UX
- שינוי צבע ראשי, צבע רקע וצבע משטח.
- שינוי משפחת גופן, גודל בסיס, עיגול פינות וצפיפות כרטיסים.
- בחירת שדות שיוצגו למשתמשים.
- איפוס הגדרות העיצוב לברירת המחדל.

גיבוי ותחזוקה
- הורדת גיבוי תוכן.
- הורדת גיבוי אדמין ראשי מלא.
- שחזור מגיבוי JSON קיים לאחר בדיקת מבנה ושלמות.
- ייצוא CSV לבקרת תוכן ב-Excel. CSV אינו גיבוי מלא ואינו מיועד לשחזור.
- בדיקת מצב האחסון המקומי.
- בדיקת שלמות הקטלוג ותיקון כשלים אפשריים.
- שחזור נקודת השחזור המקומית האחרונה.
- צפייה במצב הגיבויים ובשאלה האם יש שינויים שטרם הורדו לקובץ.
- שינוי קוד מומחה התוכן וקוד האדמין הראשי.
- שחזור קטלוג הבסיס המובנה.
- איפוס התקדמות ומועדפים.
- איפוס מלא לברירת המחדל, לאחר אישור כפול.

שמירה מקומית ושכבות זיכרון
--------------------------
כאשר המילון מופעל דרך START_MECHLEX.bat, IndexedDB הוא מאגר המצב המלא הראשי.
localStorage משמש כמראת אתחול ותאימות לנתונים מגרסאות קודמות.

המידע המקומי כולל:
- הקטלוג הערוך.
- הגדרות תצוגה ושדות.
- מועדפים, התקדמות והיסטוריית צפייה.
- מטא-נתוני שמירה וגיבוי.
- טיוטות עריכה, כאשר שכבת השמירה תומכת בכך.
- עד 10 נקודות שחזור מקומיות לפני פעולות מסוכנות.

המידע קשור לכתובת, לדפדפן ולפרופיל המשתמש. נתונים שנשמרו ב-file:// אינם אותו אזור
אחסון כמו נתונים שנשמרו ב-http://127.0.0.1:8765. לכן לאחר המעבר להפעלת BAT יש
להמשיך תמיד באותה דרך.

ניקוי נתוני האתר, החלפת פרופיל דפדפן, התקנה מחדש של Windows או עבודה במחשב אחר
עלולים להסיר את הזיכרון המקומי. גיבוי JSON חיצוני הוא שכבת ההגנה הניידת.

חמש שכבות הגיבוי
----------------
1. שמירה אוטומטית בדפדפן
   נשמרת בזמן העבודה במחשב ובפרופיל הדפדפן הנוכחיים.

2. גיבוי תוכן JSON
   תחומים, היררכיה, מושגים ותמונות מוטמעות.

3. גיבוי אדמין ראשי JSON
   גיבוי התוכן ובנוסף הגדרות UI/UX, שדות מוצגים, העדפות והתקדמות.

4. קובץ מצב אישי
   מועדפים, מצב למידה, היסטוריה והעדפות אישיות בלבד.

5. גיבוי וורד של הקוד
   עותק תיעודי של קובצי המקור בפורמט Word. הוא אינו כולל את נתוני העבודה שנשמרו
   בדפדפן ואינו מחליף גיבוי JSON.

נקודות שחזור מקומיות הן שכבת בטיחות נוספת, אך אינן גיבוי חיצוני ואינן ניידות למחשב אחר.

ניהול קובצי JSON בתיקיית backups
--------------------------------
קובצי backups אינם מתעדכנים אוטומטית, משום שהדפדפן אינו רשאי לדרוס קבצים בתיקיית
הפרויקט.

לאחר הורדת גיבוי חדש:
1. פתחו את תיקיית ההורדות.
2. ודאו שהקובץ אינו ריק וששמו כולל תאריך ושעה.
3. העתיקו אותו לתיקיית backups.
4. שמרו לפחות גיבוי תקין אחד קודם עד שבדקתם שחזור מהקובץ החדש.
5. מומלץ לשמור עותק נוסף בכונן ארגוני מאובטח או במדיית גיבוי מאושרת.

תיקיית "גיבוי וורד"
--------------------
בתוך הפרויקט קיימת תיקייה בשם "גיבוי וורד".

מטרתה:
- לשמור עותק קריא וארכיוני של קובצי הקוד, הנתונים והתיעוד.
- לאפשר עיון בקוד גם בסביבה שבה נוח יותר לפתוח Word.
- לשמר את היררכיית התיקיות ואת שמות הסיומות המקוריות.

כללים:
- כל מסמך Word נקרא בשם המקור בתוספת .docx, לדוגמה app.js.docx.
- התוכן בתוך המסמך זהה לטקסט של קובץ המקור, ללא כותרת, הסבר, מספור עמודים או
  הערות שנוספו לצורך ההמרה.
- אין להריץ או לייבא את מסמכי Word לתוך המילון.
- אין לערוך רק את מסמך Word. שינוי אמיתי חייב להתבצע קודם בקובץ המקור.
- לאחר כל שינוי בקוד, בנתונים או בתיעוד יש ליצור מחדש את מסמך ה-Word המקביל.
- אין ליצור בתוך "גיבוי וורד" עותק נוסף של תיקיית "גיבוי וורד" עצמה.

הוספת תמונות אופליין
--------------------
אפשרות א — תמונה חיצונית בתיקיית images
1. העתיקו את קובץ התמונה לתיקיית images.
2. מומלץ להשתמש בשם זהה לשם המושג, לדוגמה: דאטום.jpg.
3. עדכנו את images/catalog.js כך שיכלול את שם הקובץ המדויק.
4. לחלופין, הזינו בשדה התמונה במרכז הניהול את שם הקובץ כולל הסיומת.

סיומות נתמכות:
- jpg
- jpeg
- png
- webp
- svg

אפשרות ב — תמונה מוטמעת
- העלו תמונה דרך עורך המושג, עד מגבלת הגודל המוצגת בממשק.
- התמונה נשמרת בתוך נתוני המושג ונכללת בגיבויי JSON.
- תמונה מוטמעת מקבלת עדיפות על קובץ חיצוני.

תמונה חיצונית מתיקיית images אינה מוכפלת אוטומטית לתוך JSON. בעת העברת הפרויקט למחשב
אחר יש להעביר גם את תיקיית images ואת catalog.js.

קטלוג הבסיס לעומת נתונים מקומיים
--------------------------------
data/mechlex-data.js הוא קטלוג הבסיס שמגיע עם החבילה.
לאחר ההפעלה הראשונה, הנתונים המקומיים בדפדפן מקבלים קדימות.

לכן שינוי mechlex-data.js לבדו לא יחליף אוטומטית קטלוג שכבר נערך במחשב.
כדי להפיץ קטלוג מעודכן קיימות שלוש דרכים:
- לייבא גיבוי תוכן או גיבוי מלא דרך הממשק.
- להשתמש בפעולת "שחזר את קטלוג הבסיס המובנה" באדמין הראשי, לאחר גיבוי.
- לבצע איפוס מלא, רק כאשר רוצים למחוק את הנתונים המקומיים הקיימים.

שלמות קטלוג והגנות נתונים
-------------------------
המערכת כוללת:
- יצירת קוד ייחודי בשכפול חוזר.
- מניעת קודים ומזהים כפולים.
- ולידציה לשם מושג, הגדרה, שם תחום וקידומת.
- ניקוי קישורי related לאחר מחיקת מושג או תחום.
- ניקוי מועדפים, היסטוריה והתקדמות של פריטים שנמחקו.
- בדיקת היררכיה ושיוך מושגים לרמות קיימות.
- בדיקת קובץ JSON לפני שהוא מחליף את המצב הנוכחי.
- חתימת checksum בגיבויים חדשים.
- נקודת שחזור לפני ייבוא, מחיקה או שינוי מבני משמעותי.

שדרוג גרסה בלי לפגוע בנתונים
----------------------------
לפני כל שדרוג:
1. הורידו גיבוי אדמין ראשי מלא.
2. הורידו קובץ מצב אישי, אם נדרש.
3. העתיקו את כל תיקיית הפרויקט לתיקיית ארכיון עם מספר גרסה ותאריך.
4. אל תמחקו את הגרסה הישנה עד שהחדשה נבדקה ושוחזר בה גיבוי בהצלחה.

בעת שדרוג קוד בלבד:
1. השוו בין VERSION.txt ו-CHANGELOG_HE.txt של שתי הגרסאות.
2. החליפו רק את הקבצים שצוינו בחבילת השדרוג.
3. אל תדרסו את images, backups או data ללא כוונה מפורשת.
4. שמרו על סדר טעינת הסקריפטים ב-index.html.
5. עדכנו את מחרוזות גרסת ה-cache ב-index.html כאשר קוד או CSS השתנו.
6. עדכנו את APP_VERSION ב-app.js כאשר יוצאת גרסה חדשה.
7. הפעילו דרך START_MECHLEX.bat.
8. בדקו את הקטלוג והפעילו "בדוק את תקינות הקטלוג".
9. בדקו שמירה, סגירה, פתיחה מחדש, גיבוי ושחזור.
10. צרו מחדש את תיקיית "גיבוי וורד" לכל קובץ שהשתנה.
11. עדכנו VERSION.txt, CHANGELOG_HE.txt, TEST_REPORT_HE.txt ו-MANIFEST_SHA256.txt.

פתרון תקלות קצר
---------------
המילון נראה אך אינו מגיב:
- ודאו ש-core/boot.js קיים.
- ודאו שסדר הסקריפטים ב-index.html לא השתנה.
- פתחו Console ובדקו 404 או שגיאת init.

מופיעה אזהרה שמתחילה ב-content.js ובמילים Permissions policy violation: unload:
- אין בפרויקט קובץ content.js והמערכת אינה משתמשת באירוע unload.
- האזהרה נוצרת בדרך כלל מתוסף דפדפן שמזריק קוד לעמוד, ואינה תקלה ב-MechLex.
- אפשר לאמת זאת בחלון InPrivate שבו התוספים כבויים. אין לאפשר unload בכותרת האבטחה רק כדי להשתיק את התוסף.

מופיעה שגיאת file: URLs are treated as unique security origins:
- סגרו את index.html שנפתח ישירות.
- הפעילו START_MECHLEX.bat.
- השתמשו רק בכתובת http://127.0.0.1:8765/index.html.

הכתובת 127.0.0.1 אינה נפתחת:
- ודאו שחלון PowerShell לא נסגר.
- ודאו שהתיקייה core כוללת start-local-server.ps1.
- נסו לסגור מופע קודם ולהפעיל שוב את START_MECHLEX.bat.
- בדקו אם תוכנת אבטחה חוסמת PowerShell מקומי בהתאם למדיניות הארגון.

נתונים ישנים אינם מופיעים לאחר מעבר מ-file://:
- פתחו את הגרסה הישנה, ייצאו גיבוי.
- הפעילו דרך BAT.
- שחזרו את הגיבוי בסביבת 127.0.0.1.

תמונה אינה מוצגת:
- בדקו שם וסיומת מדויקים.
- בדקו שהקובץ נמצא ב-images.
- בדקו שהשם מופיע ב-images/catalog.js.
- בצעו Ctrl+F5 לאחר עדכון קבצים.
